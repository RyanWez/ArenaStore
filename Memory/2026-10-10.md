## Entry 1: Research & Verification — MyanMyanPay (MMPay) Gateway Integration for Telegram Bot

**Why:** Store owner evaluated integrating MyanMyanPay (https://docs.myanmyanpay.com/api/) to automate customer payments (MMQR for KBZPay, WavePay, AYA, CB) in `@arena/bot`, replacing manual bank transfer slip screenshot uploads and manual admin approvals.

**External Sources Checked:**
- Official API docs: `https://docs.myanmyanpay.com/api/`
- SDK references: `https://docs.myanmyanpay.com/sdk-node/`
- Developer Portal: `https://developers.myanmyanpay.com/applications/new`
- Main landing & pricing: `https://www.myanmyanpay.com/`
- Render Outbound IP documentation & dashboard (`https://dashboard.render.com`)

**Key Findings & Verification:**
1. **Telegram Bot Compatibility:**
   - **Allowed & fully functional:** MyanMyanPay provides a standard REST API and official Node.js SDK (`mmpay-node-sdk`). It is client-agnostic and frequently used in Myanmar Telegram bots.
   - **User Flow:** Bot requests payment -> MMPay returns EMVCo MMQR string -> Bot generates and sends QR photo to Telegram chat with countdown timer -> Customer scans with KPay/WavePay -> MMPay dispatches signed Webhook (`X-Mmpay-Signature`, `X-Mmpay-Nonce`) -> Bot auto-confirms payment and delivers items instantly.
2. **Security Whitelisting Clarification (Crucial Discovery):**
   - Developer Console (`developers.myanmyanpay.com/applications/new`) classifies **IP Whitelist as "OPTIONAL PROTECTION"**.
   - If left blank, the API relies strictly on HMAC-SHA256 signature verification and Bearer Auth.
   - **Render / Local Impact:** No static egress proxy (like Fixie) is required. Render's dynamic shared IPs (`74.220.52.0/24`, `74.220.60.0/24`) and developer localhost instances can communicate without `KA0005: IP Not whitelisted` errors as long as the IP whitelist remains unconfigured.
3. **Operational & Commercial Terms:**
   - **Pricing:** 120,000 MMK/year Developer API fee + 100 MMK per successful payment (0% MDR).
   - **KYC:** Requires NRC + Bank book (Individual) or DICA registration + Director NRC (Company).
   - **Settlement:** Batch payouts to merchant bank account on Mondays and Thursdays.
   - **Compliance:** Standard digital goods and gaming top-ups are permitted; gambling (2D/3D), forex/crypto arbitrage are strictly prohibited.
4. **Render Free Tier Gotcha:**
   - Free instances spin down after 15 min inactivity (~50s cold start). Webhook deliveries may timeout during cold starts. Mitigation: keep-alive ping via UptimeRobot/cron-job.org every 5-10 minutes.

**Local Testing Roadmap:**
- Phase 1: Setup MyanMyanPay Developer Account & obtain Sandbox App ID, Publishable Key, Secret Key.
- Phase 2: Add Sandbox credentials to `.env.local`.
- Phase 3: Setup tunnel (`ngrok http 3000`) to expose local Fastify API (`/api/webhooks/mmpay`) for async callback testing.
- Phase 4: Implement isolated test script or prototype route using `mmpay-node-sdk` to generate and verify dynamic MMQR.

## Entry 3: Branded MMQR Card, Scan Diagnostics & Merchant KYC Architecture

**Key Additions:**
1. **Branded Payment Card Design (`apps/bot/src/services/qr.service.ts`)**:
   - Upgraded raw QR rendering into a polished 620x670 PNG Payment Card canvas using `sharp`.
   - Embedded official MyanmarPay MMQR Pagoda logo (`apps/bot/assets/mmqr-logo.png`) in the center of the QR code with a protective rounded white badge.
   - Utilizes Error Correction Level 'H' (30% recovery tolerance).
   - Added subtle muted attribution text (`Powered by MyanMyanPay` in `#94A3B8`) centered at the bottom of the card canvas, matching the reference web modal design.
   - Verified 100% byte-for-byte scan accuracy using `jsQR`.

2. **Sandbox Scan Diagnostic ("Receiver Not Register")**:
   - Scanning Sandbox QR codes with real production KBZPay/WavePay apps displays "Receiver Not Register" because production bank servers only route live Central Bank registered merchant IDs.
   - Real funds cannot be sent to Sandbox test orders.
   - Sandbox testing is conducted via the Payment Simulator in the MyanMyanPay Developer Dashboard (`developers.myanmyanpay.com`), which dispatches signed webhooks to localtunnel.
   - Real KBZPay/WavePay scanning activates once Production Keys (`pk_live_...`, `sk_live_...`) are approved.

3. **Portal Distinction**:
   - **`developers.myanmyanpay.com`**: API keys, Webhooks, Sandbox simulator, technical compliance review.
   - **`merchants.myanmyanpay.com`**: Business KYC (NRC + Selfie / DICA), Bank Settlement Account (KBZ/AYA/CB passbook linking for bi-weekly Monday/Thursday payouts). KYC approval on merchant portal is a prerequisite for LIVE production keys.

4. **Git Branching Status**:
   - All code resides strictly on branch `feat/mmpay-integration`.
   - `main` branch is untouched and preserved.
