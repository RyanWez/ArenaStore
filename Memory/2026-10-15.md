## Admin Portal Vercel 500 Fix, SPA Conversion & Smart Event-Driven (Zero-Polling) Architecture

**Context:**
1. The admin portal deployed on Vercel was crashing with `500 [nuxt] instance unavailable` on unauthenticated root accesses (`/`) because route middleware (`auth.global.ts`) lost the Nuxt execution context after an `await fetchUser()` call before invoking `navigateTo('/login')`.
2. Core pages (`orders.vue`, `payments.vue`, `customers/index.vue`, `index.vue`) used high-frequency interval polling (4s/10s), generating >1,200 redundant database queries/hour per open browser tab and placing unnecessary load on the Render backend and Neon PostgreSQL.

---

### Key Changes & Optimizations

#### 1. SPA Mode Conversion & Context Resilience (`apps/admin/nuxt.config.ts`, `apps/admin/middleware/auth.global.ts`)
- Configured `ssr: false` in `apps/admin/nuxt.config.ts`. The management dashboard requires no public SEO or web crawlers; compiling as a static client-side SPA serves pages from Vercel Global Edge CDN in ~15-20ms with zero serverless cold starts.
- Enabled `experimental.asyncContext: true` to prevent any asynchronous context drops.
- Bound Nuxt application context to all route middleware redirects via `nuxtApp.runWithContext(...)`.
- Added SSR fast-path guard: unauthenticated visits without cookies redirect immediately without issuing redundant backend requests.

#### 2. Production Bundle & Edge Caching Optimizations (`apps/admin/nuxt.config.ts`, `apps/admin/composables/useSupplierStatus.ts`)
- **DevTools Disabled in Prod:** Hardcoded `devtools: { enabled: true }` replaced with `process.env.NODE_ENV !== 'production'` to shrink production bundle size.
- **Vercel Edge Caching:** Configured long-term `Cache-Control` headers in `nitro.routeRules` for `/_nuxt/**` (1 year immutable), `/logo*.png`, and `/favicon*` (7 days, stale-while-revalidate).
- **Vite Build Minification:** Enabled `cssMinify: true` and `minify: 'esbuild'`.
- **Client Cache TTL:** Added a 10-second cache TTL (`STATUS_CACHE_TTL_MS = 10000`) in `useSupplierStatus.ts` to deduplicate rapid supplier status fetches across Header and Dashboard navigation.

#### 3. Smart Event-Driven (Zero-Polling) Real-Time Architecture (`apps/admin/composables/useAdminEvents.ts`)
- **Shared Singleton SSE Connection Pool:**
  - Consolidated duplicate `EventSource` allocations into a single shared browser connection pool.
  - Reference-counted subscriptions maintain the connection across page navigation without reconnect churn, utilizing a 5-second disconnect grace timer.
- **`useSmartSync` Composable:**
  - **Zero-Polling when Live (0 requests/sec):** When the SSE stream is active, polling timers are completely paused. Updates sync instantly (<100ms) upon receiving backend events.
  - **Adaptive Fallback Safety Net:** If network connectivity drops or SSE reconnects, gentle background fallback polling activates automatically (e.g. 30s) so admins never miss orders during outages.
  - **Visibility Awareness:** Polling is completely suspended when the browser tab is hidden (`document.hidden`).
- **Core Pages Refactored:**
  - `orders.vue`: Replaced 4s polling with `useSmartSync` listening for `ORDER_CREATED` and `ORDER_STATUS_CHANGED`.
  - `payments.vue`: Replaced 4s polling with `useSmartSync` listening for `DEPOSIT_SUBMITTED` and `DEPOSIT_REVIEWED`.
  - `index.vue`: Replaced 10s polling with `useSmartSync` listening for all dashboard metric events.
  - `customers/index.vue`: Replaced 4s polling with `useSmartSync` listening for `CUSTOMER_UPDATED`, `DEPOSIT_REVIEWED`, and `ORDER_CREATED`.
  - `supplier.vue`: Added `document.hidden` check to 30s supplier balance ticker.
- **Real-Time Live Indicator (`apps/admin/components/Header.vue`):**
  - Integrated a pulsing green `Live` status badge in the top navigation bar to visually reflect active SSE streaming.

#### 4. Backend RBAC & Real-Time Event Dispatch (`apps/api`)
- Added `requireAnyPermission(permissions: string[])` in `apps/api/src/rbac/require-permission.ts`.
- Relaxed `/api/admin/events` route guard to `requireAnyPermission(["orders.view", "payments.view", "customers.view", "overview.view"])`, allowing all authorized admin roles to tap into the live SSE stream.
- Emitted `broadcastAdminEvent("CUSTOMER_UPDATED", ...)` on customer balance adjustments, deactivations, and account restorations in `apps/api/src/routes/admin.ts`.

## Bot UI & MMQR Anti-Spam / Visual Feedback Optimization

1. **Instant Telegram Chat Action (`upload_photo`):**
   - Added `ctx.replyWithChatAction("upload_photo")` immediately upon user initiating MMQR generation (`mmpay_pay_`) and re-showing invoices (`mmpay_show_`).
   - Telegram chat header instantly reflects `"sending photo..."`, giving real-time feedback while the backend requests dynamic MMQR from MyanMyanPay gateway and composites the card image.

2. **MMQR Status Check Cooldown & Anti-Spam (5 Seconds):**
   - Added `activeMmpayCheckCooldowns` guard in `apps/bot/src/bot.ts` for `mmpay_check_`.
   - If payment is still `PENDING`, a 5-second cooldown is enforced: rapid repeated clicks return an alert dialog displaying remaining seconds (`⏳ ခေတ္တစောင့်ပေးပါ... နောက်ထပ် X စက္ကန့် စောင့်ပြီးမှ ထပ်မံ စစ်ဆေးနိုင်ပါမည်။`), eliminating Telegram 429 flood control penalties and redundant database queries.
   - When payment succeeds (`COMPLETED`/`APPROVED`), cooldown is immediately cleared, the QR photo message is removed, and the success celebration card with updated wallet balance is delivered instantaneously. Cooldown is also cleared on order expiration or cancellation.

## Restocked Notification & Deep-Link Buy Flow Revamp

**Context:** Restocked broadcast messages were overly verbose and messy, containing marketing tips, pointing hand emojis, and raw deep-link hyperlinks in the message body that caused Telegram to generate massive, distracting web preview cards ("VIEW BOT"). Tapping the link triggered `/start restock_<id>`, printing an awkward `/start` bubble in the user chat.

**Changes:**
1. **Concise Restock Card (`apps/api/src/services/telegram-notifier.ts`):**
   - Streamlined `buildRestockedMessage` to a polite, 4-line blockquote card containing only essential product info (brand emoji, title, MMK retail price, and in-stock status).
   - Removed marketing filler and raw in-text hyperlinks completely.
   - Enforced `link_preview_options: { is_disabled: true }` and `disable_web_page_preview: true` in `sendTelegramMessageFloodAware` to permanently suppress preview cards.
2. **Dedicated Inline "Buy Now" Keyboard (`buildRestockedKeyboard`):**
   - Extracted direct purchase CTA into an inline button below the message: `[ 🛍️ Buy Now ]` (with `icon_custom_emoji_id: BOT_EMOJIS.BUY_NOW`).
   - Deep-link targets `?start=buy_${productId}` (falling back to `callback_data: buy_${productId}` if `TELEGRAM_BOT_USERNAME` is unset).
3. **Bot `/buy` Command & Deep-Link Router (`apps/bot/src/bot.ts`):**
   - Updated `/start` router regex to support `buy_<id>` deep-links (`/start buy_123` lands directly on the product detail stepper card).
   - Added dedicated `/buy` command (`/buy <productId>`, `/buy_<productId>`, or fallback to catalog).
   - Registered `/buy` in `BOT_COMMANDS` and Telegram menu (☰ button).
   - Added callback query handler `/^(?:prod_|buy_)(\d+)$/` with graceful fallback to `ctx.reply` if message edit fails.
4. **Verification:**
   - Unit test suites (`tests/unit/restock-notifier.test.ts`, `tests/unit/bot.test.ts`): 280/280 green.
   - Integration test suite (`tests/integration/restock-notify.integration.test.ts`): 2/2 green.
   - Full TypeScript compilation clean across `@arena/api` and `@arena/bot`.
