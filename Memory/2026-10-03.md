### 3. Key Technical Challenges & Permanent Solutions (Gotchas & Fixes)

#### 1. Render Node 24 EROFS Error (`corepack enable`)
- **Root Cause:** Render Node 24 environment mounts `/usr/bin` as read-only. Calling `corepack enable` attempted to unlink `/usr/bin/pnpm` to install corepack shims, crashing the build with `EROFS: read-only file system, unlink '/usr/bin/pnpm'`.
- **Solution:** Removed `corepack enable` from Render Build Command. Render already ships with `pnpm` pre-installed. The build command was simplified to:
  ```bash
  pnpm install --frozen-lockfile && pnpm build
  ```

#### 2. Node ESM Extensionless Import Failure (`ERR_MODULE_NOT_FOUND`)
- **Root Cause:** Compiling TypeScript with standard `tsc` does not append `.js` file extensions to relative import paths (e.g. `import "./instrument"` remained extensionless in `dist/index.js`). Pure Node.js ESM strict resolution throws `ERR_MODULE_NOT_FOUND: Cannot find module '/opt/render/project/src/apps/api/dist/instrument' imported from .../dist/index.js`.
- **Solution:** 
  1. Updated `start` scripts in `apps/api/package.json` and `apps/bot/package.json` to execute directly via `tsx src/index.ts`.
  2. Moved `tsx` from `devDependencies` to production `dependencies` in both packages.
  3. Added top-level monorepo start script in `package.json`:
     ```json
     "start": "pnpm --filter @arena/api start & pnpm --filter @arena/bot start"
     ```

#### 3. Telegram API Cold-Start Timeout (`ETIMEDOUT` in `bot.api.getMe()`)
- **Root Cause:** When the free Render container spins up (cold start), initial TCP handshake between Render Singapore container and Telegram's European servers (`api.telegram.org`) occasionally exceeds 30 seconds, returning `FetchError: request to https://api.telegram.org/bot<TOKEN>/getMe failed, reason: ETIMEDOUT`. The previous implementation called `await bot.api.getMe()` at root startup without error trapping, exiting the bot with code 1 (`[ELIFECYCLE] Command failed with exit code 1`). Because the bot was running alongside the API, Render killed the entire container (`Exited with status 1`).
- **Solution ([apps/bot/src/index.ts](file:///home/zixuan/Projects/Arena%20Store/apps/bot/src/index.ts)):**
  1. Wrapped `getMe()` and command registration in a continuous retry loop with exponential backoff:
     ```typescript
     let botInfo: any = null;
     while (!isShuttingDown) {
       try {
         if (!botInfo) {
           try {
             botInfo = await bot.api.getMe();
             console.log(`🤖 Arena Store Telegram Bot running as @${botInfo.username}`);
             await bot.api.setMyCommands([...]).catch(() => {});
           } catch (connErr: any) {
             console.warn(`[Telegram Bot] Connection failed (${connErr.message}). Retrying in 5s...`);
             await new Promise((resolve) => setTimeout(resolve, 5000));
             continue;
           }
         }
         isPolling = true;
         bot.botInfo = botInfo;
         await bot.start({
           onStart: (info) => console.log(`🚀 Storefront bot @${info.username} listening!`),
         });
       } catch (err: any) {
         isPolling = false;
         if (isShuttingDown) break;
         console.warn(`[Telegram Bot] Polling interrupted (${err.message}). Reconnecting in 5s...`);
         await new Promise((resolve) => setTimeout(resolve, 5000));
       }
     }
     ```
  2. The bot process now recovers autonomously from any transient network drop without terminating Node or exiting Render.

#### 4. UptimeRobot Root Endpoint 404 False Alarm
- **Root Cause:** Uptime monitors pinging the domain root `https://arenastore-backend.onrender.com/` received HTTP 404 because Fastify only exposed `/health`. This marked the monitor as "Down" (Red).
- **Solution ([apps/api/src/routes/health.ts](file:///home/zixuan/Projects/Arena%20Store/apps/api/src/routes/health.ts)):**
  Added root `GET /` handler returning HTTP 200 OK:
  ```typescript
  server.get("/", async () => {
    return {
      status: "ok",
      service: "Arena Store API & Telegram Bot",
      healthEndpoint: "/health",
      timestamp: new Date().toISOString(),
    };
  });
  ```

#### 5. Dynamic Nitro Reverse Proxy for Admin Portal on Vercel
- **Root Cause:** `apps/admin/nuxt.config.ts` had a static proxy pointing to `http://localhost:4000/api/**`, causing all browser API requests in production to fail.
- **Solution ([apps/admin/nuxt.config.ts](file:///home/zixuan/Projects/Arena%20Store/apps/admin/nuxt.config.ts)):**
  Configured Nitro `routeRules` to dynamically read `API_BASE_URL` or `NUXT_PUBLIC_API_URL`:
  ```typescript
  nitro: {
    routeRules: {
      '/api/**': {
        proxy: `${(process.env.API_BASE_URL || process.env.NUXT_PUBLIC_API_URL || 'http://localhost:4000').replace(/\/+$/, '')}/api/**`,
      },
    },
  },
  ```
