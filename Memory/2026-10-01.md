## 6. Critical System Audit: 7 Core Flaws, User Decision on Catalog Simplification & Realignment

### 1. The 7 Critical Flaws Identified During System Audit
1. **Mock Deliveries in Production Bot (`apps/bot/src/services/order.service.ts`):**
   - The bot generates fake credentials (`user.xxxx@arenastore.mm`, random keys) and **never calls the upstream XPro Partner API (`POST /orders`)**.
   - Digital credentials are saved unencrypted in `order_deliveries.encryptedPayload` as raw text instead of using AES-256-GCM.
2. **Product Categories `NULL` in Database (Category Filtering Bug):**
   - `syncProducts()` inserts products without populating `categoryId`, leaving them all `NULL`.
   - In the Telegram bot, this caused all products to fallback to Category 1, breaking browsing for all other categories.
3. **Product ID vs. Upstream Product ID Confusion (Foreign Key Risk):**
   - In bot catalog query, `id` was mapped to `products.upstreamProductId`.
   - When inserting into `order_items`, `productId` references `products.id` (internal serial ID), causing FK violations or pointing to wrong items.
4. **Admin Panel Deposit Slip Image Loading Failure:**
   - Bot saves Telegram `file_id`. The browser cannot load `file_id` as an image URL.
   - Admin panel fell back to a dummy Unsplash placeholder because no Telegram file proxy endpoint exists in `apps/api`.
5. **Admin Categories Page is 100% Mock & Unnecessary:**
   - `apps/admin/pages/categories.vue` has hardcoded mock data, does not query the API, and does not persist changes.
   - More fundamentally: creating a separate manual category management UI duplicates upstream catalog structure without adding value.
6. **Admin Orders Page Mock Actions:**
   - "Refund to Wallet" and "Resend Credentials" are fake UI timeouts (`setTimeout`) with toasts, failing to update PostgreSQL or notify Telegram.
7. **Architectural Boundary Violations (AGENT.md Rules 31 & 38):**
   - `apps/bot` bypasses `apps/api` and queries PostgreSQL and XPro API directly with duplicated order and catalog logic.

### 2. User Strategic Decision & Architectural Realignment
- **Eliminate Admin Categories CRUD (`/categories`):**
  - Upstream XPro Partner API already defines products and their categories.
  - Arena Store does not need a redundant manual category management layer in Admin.
  - The Admin UI must focus purely on:
    1. **Products & MMK Pricing:** Managing exchange rates, profit margins, local overrides, and active toggles.
    2. **Deposit Slips:** Verifying KPay/WavePay payments and crediting customer wallets.
    3. **Product Orders:** Viewing real fulfillment status and genuine upstream delivery data.
    4. **Settings & Rates:** Global USD/MMK exchange rates and Myanmar payment accounts.
- **Pure Upstream Product Synchronization:**
  - Upstream API is the single source of truth for products, stock, and delivery types.
  - Arena Store's core responsibility is strictly:
    - Converting USD costs into Myanmar Kyats (MMK) at configured rates and margins.
    - Handling Myanmar customer payments via KPay and WavePay.
    - Maintaining atomic customer wallet balances and ledgers.
    - Placing genuine upstream orders (`POST /orders`) with idempotency when customers purchase.
    - Delivering genuine accounts/keys securely to the customer's Telegram chat.
