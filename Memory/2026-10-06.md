## 1. Entry: Multi-Supplier Architecture (DigitalCore Integration) — Master Plan & Milestone Execution

### Context & Decisions Made:
- **Decision on Multi-Supplier:** Dual-supplier strategy approved to eliminate single point of failure (XPro + DigitalCore).
- **Confirmed Decisions (§B3):**
  1. *Twin Products:* v1 keeps separate rows per supplier. Admin can filter via tabs (`All`, `XPro`, `DigitalCore`). Auto-failover deferred to v2.
  2. *Retail MMK Pricing:* Based on Tier-0 (`minQty: 1`) upstream price; backend accounting handles quantity wholesale tiers.
  3. *Security & Key Rotation:* API key rotated in `@DCoreStoreBot`; stored only in untracked `.env`. Default category is `uncategorized` on initial sync (non-clobbering admin overrides).
  4. *Balance Alert Threshold:* Set to **$5.00 USD** (`appSettings.supplier.balanceAlertThresholdUsd = 5`), alerting admin via `telegram-notifier`.
  5. *Customer Insufficient Balance Handling:* Masked as temporary out-of-stock/unavailable to customers while notifying admin privately.
