# Customers Page — Smooth Transition + Professional Delete System Plan

## ရည်မှန်းချက် (User Requirements)
1. **Flicker လုံးဝမဖြစ်အောင်** — 3s polling က rows တွေကို တစ်ခါတည်း အစားထိုးတာကြောင့် ခုန်/ပျောက်-ပြန်ပေါ်တာတွေ smooth ဖြစ်အောင် ပြင်မယ်
2. **Professional Delete** — Soft Deactivate (Undo/Restore နှင့်) က အဓိက၊ Deactivated tab ထဲမှာ permanent Hard Delete (typed-name confirm နှင့်)
3. **Bot Enforcement** — Deactivate လုပ်ခံရတဲ့ user က Telegram bot ကနေ order မလုပ်နိုင်အောင် ပိတ်မယ်
4. **Optimize** — Search/filter/sort/pagination ကို SQL level ကို ရွှေ့မယ် (လက်ရှိ JS in-memory ဖြစ်နေတာ)

---

## Phase 1 — Backend API (`apps/api/src/routes/admin.ts`)

### 1a. GET /api/admin/customers — SQL Pagination + Status Filter
- Query params အသစ်: `page`, `pageSize` (default 20, max 100), `statusFilter` (`active` | `deactivated` | `all`, default `active`)
- Search/balanceFilter/sortBy ကို JS filter (admin.ts:1027-1058) ကနေ **SQL** ထဲ ရွှေ့ — `ilike` search (telegramId/username/name/numeric id), `where` balance filter, `orderBy` sort
- Return မှာ `total`, `page`, `pageSize` ထည့် (pagination footer အတွက်) — `stats` KPI က global အတိုင်းထား

### 1b. Deactivate / Restore / Hard Delete Routes (အသစ် ၃ ခု)
- **POST `/api/admin/customers/:id/deactivate`** — zod validate (`reason?`); guards: ADMIN ဖြစ်နေရင် ပိတ်၊ ရှိပြီးသား DEACTIVATED ဆိုရင် idempotent 400; `db.transaction` ထဲမှာ `users.status='DEACTIVATED'` + **`audit_logs` entry** (`CUSTOMER_DEACTIVATE`, actor = request.adminUser) — audit_logs table က ရှိပြီးသား (packages/db/src/schema/audit.ts) ဒါပေမယ့် order.service.ts:266 မှာပဲ တစ်ခေါက်သုံးဖူးတာ
- **POST `/api/admin/customers/:id/restore`** — status ကို `ACTIVE` ပြန် + audit log
- **DELETE `/api/admin/customers/:id`** (permanent) — guards: status က DEACTIVATED ဖြစ်မှ ခွင့်ပြု (soft-delete မလုပ်ရသေးရင် ငြင်း)၊ `orders` count > 0 ဆိုရင် clear error message နဲ့ ငြင်း (FK NO ACTION ကြောင့် DB ကလည်း ပိတ်မယ် — orders.ts:11-13)၊ ADMIN မဖြစ်ရ
  - `db.transaction` ထဲမှာ: audit snapshot (wallet balance, topups count ပါ jsonb) အရင် insert → user delete (wallets/wallet_ledger/topup_requests cascade ဖြင့် ပျက် — wallets.ts, topups.ts)
- အားလုံး error shape `{ ok:false, error }` လိုက်နာ

## Phase 2 — Bot Enforcement (`apps/bot`)

- `getOrCreateUser` (apps/bot/src/services/order.service.ts:60) က user resolve ပြီးတဲ့အခါ `user.status !== 'ACTIVE'` ဆိုရင် blocked flag return — profile sync က status ကို မထိအောင် သတိထား (လက်ရှိ code က နာမည်/username ပဲ update လုပ်တာ အသင့်)
- bot.ts ရဲ့ command/message entry တွေမှာ blocked ဆိုရင် ဖော်ပြချက် message ("Your account has been suspended…") နဲ့ ရပ်မယ် — bot ရဲ့ ရှိပြီးသား message style လိုက်နာ
- Deactivated user ဘယ်လောက်ပဲ bot ပြန်ဖွင့်ဖွင့် status မပြန်ဖြစ်ရ

## Phase 3 — Admin UI (`apps/admin/pages/customers.vue`)

### 3a. Flicker Fix + Smooth List (အဓိက တောင်းဆိုချက်)
- **Merge-by-id polling**: `fetchCustomers(true)` က `customers.value = res.customers` (customers.vue:92) တစ်ခါတည်း အစားထိုးတဲ့အစား row data ကို **id နဲ့ in-place merge** လုပ်မယ် — Vue DOM identity မပျက်၊ scroll position မခုန်
- **No-op skip**: payload အရင်nikids တူနေရင် re-render မလုပ် (cheap stringify compare)
- **`<TransitionGroup>` on tbody rows**: customer အသစ် fade+slide-in၊ ဖယ်ထုတ်လိုက်တဲ့ row က အနေအထားကနေ smooth ထွက် (leave animation)၊ sort ပြောင်းရင် rows ရွှေ့သွားတာ animate — `prefers-reduced-motion` က main.css:89-99 မှာ ရှိပြီးသား လေးစားမယ်
- **Stale-while-revalidate filters**: search/filter ပြောင်းလို့ fetch လုပ်နေစဉ် list အရင်nikids မှေးမှိန် (opacity + top progress bar) — skeleton က initial load မှာပဲ
- **Pagination footer**: orders.vue:162-215 + 590-642 က pattern ကို port — page numbers + ellipsis, prev/next, 10/20/50 per-page; server-driven (Phase 1a)

### 3b. Professional Delete Flow
- Actions column မှာ **Trash icon (နီရောင်)** — နှိပ်လိုက်ရင် **Deactivate Confirm Dialog** (payments.vue:767-823 Reject dialog style): impact summary (name, balance, orders count), reason (optional), inline spinner — တစ်ခါတည်း မဖျက်ဘူး
- Confirm ပြီးရင် row က TransitionGroup leave animation နဲ့ ထွက် → **Undo toast (10s)** ပေါ် → undo နှိပ်ရင် restore API ခေါ်
- **Deactivated tab** (statusFilter): deactivated customers ကို ကြည့်လို့ရ + Restore action
- **Hard delete**: Deactivated tab ထဲမှာသာ — **typed-name confirmation** dialog (customer name အတိအကျ ရိုက်မှ button enable)၊ orders ရှိနေရင် ဘာကြောင့်မရလဲဆိုတာ ရှင်းပြပြီး disable

### 3c. Consistency Polish (orders/payments နဲ့ တူအောင်)
- PrimeVue `<Skeleton>` rows (custom div skeletons အစား)
- Adjust modal + slip preview မှာ `<Transition name="modal">` + `.modal-card` + `@click.self` + **Escape key** (လက်ရှိ customers.vue modal တွေမှာ မရှိ)
- Sticky filter bar (orders.vue:366 style)

### 3d. Toast System — Undo Support
- `useToast.ts` + `ToastContainer.vue` မှာ optional **action button** (label + handler + countdown) ထည့် — Undo feature အတွက်

## Phase 4 — Tests (`tests/unit/admin-customer-deletion.test.ts`)
`admin-order-actions.test.ts` pattern လိုက်နာ:
- Deactivate: status ပြောင်း + audit log ရေး + ADMIN ငြင်း
- Restore: status ပြန် ACTIVE
- Hard delete: orders ရှိရင် ငြင်း / orders မရှိရင် user + wallet + topups cascade ပျက် / DEACTIVATED မဖြစ်ရသေးရင် ငြင်း
- List: deactivated default မှာ မပါ / statusFilter=all မှာ ပါ
- Bot: status !== ACTIVE ဆိုရင် blocked
